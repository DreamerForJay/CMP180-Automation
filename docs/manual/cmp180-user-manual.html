CH 0給第一次看到這份文件的人

你不需要先懂程式，也不需要先懂無線電。這一章用最白話的方式，讓你在五分鐘內知道「這東西是幹嘛的」、「我會碰到哪些名詞」、以及「我屬於哪一種使用者」。

0.1　這套系統在做什麼？

想像你做了一台 Wi-Fi 裝置（手機、路由器、無線網卡）。你要怎麼知道它發出來的無線訊號「乾不乾淨」？

工程上會用一台叫做 R&S CMP180 的專業儀器來量。這台儀器很貴、很複雜，而且原本要靠人一步一步在儀器畫面上點選設定、按下開始、等結果、再手動抄下數字。一次量測可能要點十幾個按鈕，量二十個頻率點就要重複二十次。

這個專案做的事很單純：把「人手動點儀器」變成「電腦自動做」，並且把每一次量測的設定、原始回應、結果、圖表都完整存檔，之後任何人都能回頭查證。

① 自動設定儀器

把頻率、頻寬、功率等參數一次送給 CMP180，不用人工在儀器面板上點。

② 自動執行與收資料

啟動量測、等待完成、讀回 EVM／功率／頻率誤差等數十個欄位。

③ 自動存檔與畫圖

每次執行都產生 CSV、JSON、metadata 與可離線開啟的 HTML 報告。

④ 自動守安全規則

開啟射頻（RF）前強制檢查接線與人員在場，結束一定關閉射頻。

一句話總結

這是一個跑在你自己電腦上的網頁工具：打開瀏覽器、填幾個欄位、按執行，它就會幫你操作 CMP180 儀器（或用模擬資料示範），並把結果存成可稽核的檔案。

最重要的一條安全原則

只要你沒有站在 CMP180 旁邊、沒有親眼確認接線，就永遠使用 --demo-only 示範模式。示範模式不會連線儀器、不會送出任何指令、不會開啟射頻。

CH 2安裝步驟（逐步照做）

怎麼打指令？

按 Win + X → 選「終端機 (Terminal)」或「Windows PowerShell」。看到一行結尾是 > 的提示字元後，把下面框框裡的指令整行複製貼上，再按 Enter。
框框裡如果出現行尾的 `（反引號），那是 PowerShell 的「換行接續」符號，整段一起複製即可。

2.1　取得專案並進入資料夾

git clone https://github.com/DreamerForJay/CMP180-Automation.git
Set-Location CMP180-Automation

Set-Location 就是「切換目前所在資料夾」的意思（等同其他系統的 cd）。之後所有指令都要在這個資料夾裡執行。

確認自己在正確位置：

Get-Location

輸出結尾應該是 ...\CMP180-Automation。

2.2　建立虛擬環境（venv）

虛擬環境是什麼？想像它是一個獨立的小房間，這個專案需要的套件都裝在這個房間裡，不會弄亂你電腦上其他 Python 程式。這是標準做法，請不要跳過。

py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

成功的話，提示字元前面會多出 (.venv) 字樣，像這樣：

(.venv) PS C:\work\CMP180-Automation>

如果出現「因為這個系統上已停用指令碼執行」

這是 Windows 的安全設定。在同一個視窗執行下面這行後再試一次啟用：

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

-Scope Process 代表只對目前這個視窗生效，關掉視窗就恢復原狀，不會改到系統全域設定。

2.3　安裝套件

一般使用者 / 示範模式（不接儀器）：

python -m pip install -e ".[dev]"

要接真實 CMP180 儀器時，額外需要儀器通訊套件：

python -m pip install -e ".[dev,hardware]"
安裝選項裝了什麼什麼時候需要
（基本）matplotlib、pandas、pyyaml、pydantic一定會裝，負責畫圖、資料處理、設定檔驗證
[dev]pytest、pytest-cov、ruff、mypy執行測試與程式碼檢查；建議一般使用者也裝
[hardware]RsInstrument只有要連真儀器時才需要
[build]pyinstaller要把程式打包成 .exe 時才需要

這一步會下載數百 MB 的套件，請耐心等待。看到最後出現 Successfully installed ... 就完成了。

2.4　確認安裝成功（三個檢查）

  1. 檢查設定檔能被讀懂 
    python -m cmp180_evm validate-config configs\instrument.example.yaml
python -m cmp180_evm validate-config configs\wlan_baseline.example.yaml
    看到 OK (instrument) 與 OK (wlan_baseline) 代表通過。
  2. 執行自動測試 
    python -m pytest -m "not hardware"
    -m "not hardware" 代表「跳過需要真儀器的測試」。看到一整排綠色的 passed 就成功。
  3. 啟動介面 
    python -m cmp180_evm.web --demo-only
    畫面出現網址後，用瀏覽器開啟 http://127.0.0.1:8765。

到這裡就裝好了

之後每次要使用，只需要三步：① 開終端機 → ② Set-Location 到專案資料夾 → ③ 啟用 .venv 後啟動網頁。不必再重裝。

CH 3五分鐘上手（示範模式）

這一章帶你完整跑一次流程。全程不會連線儀器、不會發射任何訊號，放心操作，按錯也不會有任何後果。

3.1　啟動

# 1. 進入專案資料夾（路徑換成你自己的）
Set-Location C:\work\CMP180-Automation

# 2. 啟用虛擬環境
.\.venv\Scripts\Activate.ps1

# 3. 以純示範模式啟動網頁介面

終端機會顯示類似：

CMP180 Web GUI: http://127.0.0.1:8765

看懂這兩行

  • http://127.0.0.1:8765 —— 127.0.0.1 是「你自己這台電腦」，代表這個網頁只有你看得到，不會被別人連進來。
  • MOCK only; real-hardware controls are locked —— 實機功能已鎖定，這一輪絕對不會碰儀器。

把這個終端機視窗留著不要關。它就是伺服器本體，關掉網頁就打不開了。要結束服務時，在這個視窗按 Ctrl + C。

3.2　第一次操作流程

  1. 打開瀏覽器輸入 http://127.0.0.1:8765。首頁會顯示 CMP180 的外觀渲染圖與系統架構說明。
  2. （可選）玩一下 3D 檢視按「啟用 360° 檢視」，可以拖曳旋轉、滾輪縮放，下方有正面／背面／側面／重設／自動旋轉／全螢幕。這只是外觀展示，不會連線儀器。
  3. 切換主題與語言右上角可切換亮／暗主題（預設暗色，選擇會記在瀏覽器裡）與中文／EN。切換語言不會重新送出量測。
  4. 進入「量測」頁 → 選「示範單點」保留預設值：頻率 6105 MHz、頻寬 320 MHz、功率 −40 dBm，按「執行 Mock 單點」。
  5. 看結果畫面會切到「結果與圖表」，並標示 示範資料 / DEMO DATA。你會看到 EVM、Burst Power、Frequency Error 三個主要數字。
  6. 跑一次掃描切到「示範頻掃」，輸入起始 5925、結束 6125、步進 20（MHz），執行。應該產生 11 個資料點與一張曲線圖。
  7. 試試取消掃描進行中按「停止」。系統會在目前這一點完成後安全停止，並保留已完成的部分結果（partial result），不會整批丟掉。
  8. 下載產出結果頁下方有 CSV、JSON、Metadata、HTML Report 按鈕，點下去就能開啟。
  9. 回頭查紀錄進入「量測紀錄」頁，按「重新整理」，剛剛跑的每一次都會列在這裡，可依時間排序、開啟檔案，也可勾選 2–8 筆做比較。

示範資料要怎麼認？

畫面上會標 示範資料 / DEMO DATA，而且存檔的 metadata 裡 simulated=true。這些數字不能當成任何儀器或產品的實測結果。

CH 5功能逐項說明

量測頁下面有多個分頁。前面幾個是「示範」，永遠安全；後面幾個會碰真儀器。這一章逐一說明每個分頁在做什麼、欄位怎麼填、結果怎麼看。

先記住這個分界

名稱有「示範 / Demo / Mock」的分頁，永遠不會送出 SCPI、不會開啟 RF。它們是給教學、UI 驗證、持續整合測試，以及沒有儀器時的開發使用。

5.1　示範單點量測

在做什麼：模擬「在單一頻率量一次」的完整流程。

欄位意思建議值
Frequency（頻率）要量測的中心頻率6105 MHz
Bandwidth（頻寬）訊號佔用的頻寬320 MHz
Power（功率）訊號的功率大小，dBm 越小越弱−40 dBm

結果：EVM、Burst Power、Frequency Error 三個主要數字，以及 VALID 狀態，並產生一個 run 資料夾。

5.2　示範頻率掃描

在做什麼：固定功率，從起始頻率一路量到結束頻率。用來看「這個裝置在不同頻道上表現一不一致」。

欄位意思
Start（起始頻率）從哪裡開始，例如 5925 MHz
Stop（結束頻率）量到哪裡，例如 6125 MHz
Step（步進）每次跳多少，例如 20 MHz
Dwell（停留）每一點停留多久再讀值

測點數怎麼算

(Stop − Start) ÷ Step + 1。例如 (6125 − 5925) ÷ 20 + 1 = 11 點。步進設太小會產生非常多點，執行時間會拉很長。

執行控制：掃描使用非同步工作（Job）機制，狀態會依序經過 queued → running → complete，中途可 stopping／cancelled，錯誤則為 failed。同一時間只允許一個進行中的工作。

5.3　示範功率掃描

在做什麼：固定頻率，改變輸出功率，看 EVM 如何隨功率變化（Power vs EVM）。這是判斷功率放大器線性度的典型測試。

填寫固定頻率、起始功率、結束功率、步進（例如 −60 到 −40 dBm、每 5 dBm 一點 → 5 個點）。執行後圖表的 X 軸會自動從「頻率」切換成「dBm」。

5.4　進階 PA 指標示範

離線分析用的進階功率放大器指標展示。

邊界說明

此頁的進階指標目前多數標示為 SIMULATED 或 DERIVED（模擬或推導），不能當作 DUT 的實測性能。

5.5　Constellation 星座圖

在做什麼：把調變訊號畫成平面上的一堆點。點越集中在理想位置，訊號品質越好；點散開成一團雲，代表雜訊或失真嚴重。

支援的調變方式

BPSK、QPSK、16-QAM、64-QAM、256-QAM、1024-QAM、4096-QAM，皆以單位平均功率的理想點呈現。

可以調整的損傷參數

參數白話意思
AWGN加入隨機雜訊，點會散開

5.6　MCS Sweep

在做什麼：MCS（Modulation and Coding Scheme）是 Wi-Fi 的「檔位」，數字越大代表用越複雜的調變傳越快，但也越難維持品質。此頁掃描 EHT MCS 0–13 的表現。

  • 可輸入逗號分隔、不連續、保留順序的清單，例如 0,3,5,7,9,11。
  • 輸出 modulation、coding rate、EVM、power、frequency error、reliability、validity。
  • 圖表可切換 EVM vs MCS 與 Power vs MCS。
  • 匯出 mcs_sweep.csv、.json、SVG、PNG 與 metadata。

目前狀態：HIL PENDING

Mock 結果固定標記 source=mock、simulated=true、hil_status=HIL_PENDING，而且沒有正式的合規門檻。CMP180MCSSweepSource.acquire() 同樣會拒絕執行，直到 waveform／MCS 對應關係有官方文件或實機證據為止。

5.8　GPRF 能力掃描

在做什麼：用 CMP180 的通用射頻（General Purpose RF）產生器與量測功能，展示儀器本身的「調頻能力」與「功率量測能力」。可在 400 MHz–8 GHz 規劃頻率掃描，或在固定頻率下規劃功率掃描。

結果代表什麼、不代表什麼

GPRF 的欄位是 measured_power_dbm 與 reliability，不是 WLAN EVM，也不是 OFDM 解調結果，更不得作為任何合規宣稱。它回答的是「儀器本身準不準」，不是「產品好不好」。

怎麼讀圖

掃描軸圖表標題Expected Power 參考線適合判讀
Frequency 軸GPRF Frequency Sweep – Power Flatness固定功率的水平線功率平坦度
Power 軸GPRF Power Sweep – LinearityExpected = Generator Power 的對角線線性度

實測功率以高對比藍色曲線顯示，Expected Power 以橘色虛線標出。Power Error (dB) = measured − expected；切到該指標時，0 dB 參考線代表完全貼齊設定功率。

Summary 直接顯示：Average Power、Expected Power、Mean Error、Max |Error|、Peak-to-Peak Ripple、Std Dev 與 Valid 點數。

安全行為

若任一點出現 SCPI 錯誤、reliability 非 0，或觸及頻譜分析儀安全上限，系統會在該點 STOP／RF Off 後停止後續掃描，並保存已完成的部分結果。

5.9　Loopback RF 效能驗證

以獨立重複量測（repeats）檢查穩定性與合理性，並標示離群值（outlier），產出對應 artifacts。用來確認整條量測鏈路（儀器＋線材＋軟體）是否穩定，而不是評估產品。

5.10　HIL 批次執行器

在做什麼：把多個待驗證的實機案例排成一張矩陣，依重要度逐一執行，並把進度存檔。

5.11　Path Loss 校正

為什麼需要校正：訊號從儀器出來、經過線材與接頭，到達接收端時已經衰減了一些。校正就是量出「路上掉了多少 dB」，之後把它補回去，結果才代表真正的參考面功率。

校正頁有 7 個欄位，每個欄位名稱都可以直接點擊聚焦，右上角的 ? 按鈕提供說明。支援先建立草稿、檢視後再正式套用。

目前重要限制

Power Reference Plane 尚未套用正式的 Path Loss／Calibration Profile，metadata 會標示 calibration_applied=false。因此目前不能把設定值（例如 −45 dBm）解讀成「已補償後的正式參考面功率」。

  2. 公司產品規格與保護帶（guard band）
  3. DUT 的操作模式、通道、功率、鏈路數、溫度與校正條件
  4. 線材／路徑損耗、外部衰減與量測不確定度

CH 8實機操作與 RF 安全

這一章是強制閱讀，不是建議

實機模式會讓儀器真的輸出射頻能量。操作錯誤可能造成儀器輸入端過載損壞，或產生不該存在的無線發射。沒有把握就不要執行。

8.1　七條不可妥協的安全規則

  1. 未經明確要求，不得 Reset 儀器或 Workspace。別人可能正在使用同一台儀器的其他設定。
  2. 預設只讀（query-only）。FETCh 只讀取已儲存的結果；READ 與 INITiate 會啟動新的量測，不可互相替換。
  3. 開啟 RF 前必須逐項確認：接線路徑、頻率、頻寬、功率、線材／衰減器、DUT 狀態、分析儀輸入上限。
  4. 所有 RF 流程結束後必須 Stop／Abort 並 RF Off —— 不論是成功、錯誤、逾時還是取消。
  5. SCPI 指令只能來自 command map 與 typed registry。未驗證的命令一律保持 null 或 HIL_PENDING，絕不從其他儀器猜指令。
  6. Mock、合成資料、既有檔案分析與 UI 預覽都不算新的實機驗證。
  7. 操作員必須在場。不可遠端或無人執行任何會開啟 RF 的步驟。

原因：你用的 Python 版本太舊。

網頁打不開 / 顯示「無法連上這個網站」

檢查順序：

  1. 啟動伺服器的那個終端機視窗還開著嗎？關掉視窗＝關掉伺服器。
  2. 網址是不是 http://127.0.0.1:8765？注意是 http，不是 https。
  3. 終端機有沒有印出錯誤訊息？

原因：更新程式後，仍有舊的 Python Web 程序佔用同一個連接埠，請求隨機落到舊版本。

解法：

  1. 在啟動 Web 的 PowerShell 視窗按 Ctrl+C 正常關閉。
  2. 確認沒有其他視窗還在跑 python -m cmp180_evm.web。
  3. 重新啟動一次。

預防：新版伺服器使用獨占式綁定（exclusive bind），第二個相同 host／port 的實例會在啟動時直接失敗。不要同時開多個 python -m cmp180_evm.web。

介面右上角顯示 LOCKED，實機按鈕點不動

原因：這次是以 --demo-only 啟動的。這是正常且安全的狀態。

解法：若你確實要操作儀器，停止伺服器後改用：

python -m cmp180_evm.web --host 127.0.0.1 --port 8765

實機頁送出後被拒絕，顯示「不可執行」與一段原因

原因：preview 檢查判定你這組參數超出目前 RF workflow 允許的 routing、bandwidth、power、dwell 或點數範圍。

這是保護機制，不是故障。系統不會偷偷改跑一組已驗證的參數來讓你「看起來成功」。

解法：依畫面顯示的拒絕原因調整參數；若確實需要新的能力範圍，必須先補進正式 command registry、workflow 與 capability profile 並完成驗證。

連不到儀器 / test-connection 失敗

逐項檢查：

  1. 網路線接好了嗎？控制電腦的 IP 是否在 192.168.200.0/24？
  2. Test-NetConnection 192.168.200.50 -Port 5025 是否成功？
  3. CMP180 與 CMsquares 是否已啟動？
  4. 是否有 IP 衝突（別台電腦用了同一個 IP）？
  5. 是否安裝了 [hardware] 選項（RsInstrument）？
結果全部顯示 INVALID

常見原因：訊號沒進到分析器（線沒接好）、功率設定與 Expected Nominal Power 差太多、或量測尚未完成就讀取。

重要：INVALID 不可以當成 0 來處理，也不可以在報告中忽略不提。系統刻意保留 null / valid=false 就是為了避免造假。

匯出按鈕是灰的，顯示「目前沒有可匯出的測點」

原因：圖表目前沒有任何有效測點。

這是刻意的防呆，避免匯出一個空白卻看起來很正式的報告。等取得測點後會自動恢復。

原因：Web 伺服器在該案例執行中被重啟，背景執行緒已消失。

解法：重新按「準備／重新檢查矩陣」後才能再跑。這個設計是為了不把消失的執行緒誤標成「執行中」。

掃描中途停了，只有一部分的點

可能原因：你按了 Stop、某一點回傳 INV、SCPI 錯誤、reliability 非 0，或觸及安全上限。

系統行為：在該點完成 STOP／RF Off 後停止後續掃描，並保存部分結果。結果頁會同時列出有效與無效／未完成的點數。

注意：部分結果不能描述為「通過」。

CH 12延伸問題 Q&A

我沒有 CMP180 儀器，這套東西對我還有用嗎？

有。示範模式提供完整的操作流程、圖表、匯出與報告，適合教學、介面驗證、流程練習，以及在沒有儀器時繼續開發。你唯一得不到的是「真實的量測數字」。

示範資料是隨便亂數產生的嗎？

不是隨機亂噴。Mock 會模擬合理的物理趨勢（例如 EVM 隨功率變化），讓圖表看起來像真的量測。但它一律標記 simulated=true，而且輸出 schema 與實機完全相同，所以可以用來驗證整條資料流。

為什麼 Constellation 和 MCS Sweep 不能接真儀器？功能不是都寫好了嗎？

因為專案內還沒有已驗證的 CMP180 擷取指令與回傳格式。

這是刻意的決定：寧可讓功能停在「拒絕執行」，也不放猜測的 SCPI 指令進系統。猜錯的指令可能造成儀器進入非預期狀態，或產生看似合理卻完全錯誤的數字 —— 後者更危險，因為沒人會發現。

解鎖條件是：官方 CMP180 文件、儀器內建 Command Help、SCPI Recorder 紀錄，或受控的實機探索證據。

我可以把這個網頁介面開放給同事從別台電腦連嗎？

目前不行。系統禁止綁定非 loopback 位址，只能在本機使用。原因是硬體模式沒有登入與權限控制，開放出去等於讓任何人都能操作一台會發射射頻的儀器。

「完成」和「通過」差在哪？

完成（complete）＝量測流程順利跑完，儀器沒報錯，該收的資料都收到了。

通過（pass）＝數字符合某個門檻。

系統會在結果頁主動提醒你這兩件事不一樣。目前沒有正式核准 limit profile 的實機結果，只會標示 MEASURED，不宣稱 PASS。

為什麼中途取消時，已經量到的資料不會全部丟掉？

因為那些點是真的量到的，丟掉就浪費了現場時間。系統採用協作式取消：只在目前這一點完成 STOP 與 RF Off 之後才停，並保存 partial artifacts，同時在結果中明確標示「部分／取消」與完成點數，不會讓人誤以為是完整資料。

我改了參數，系統會不會偷偷幫我換成「安全的」設定去跑？

不會，而且這是明確的設計原則。如果你的輸入超出目前 workflow 允許的範圍，系統會顯示拒絕原因並停住，不會改跑已驗證的 6085／6105／6125 MHz 固定 profile。這樣你才不會誤以為自己的參數已經被驗證過。

切換中英文或亮暗主題，會不會重新量測？

不會。切換語言會更新紀錄狀態、通知、結果摘要與圖表說明的文字，但不重新送出量測或 RF 請求；原始診斷內容也會保留原文不翻譯。主題選擇存在瀏覽器的 localStorage，下次開啟會延續。

我可以拿這些結果去申請認證或寫進產品規格書嗎？

目前不行。理由在 CH 6.5 與 CH 11 已說明：

  • 目前是儀器自打自收的 loopback，沒有 DUT。
  • Power Reference Plane 尚未套用正式校正（calibration_applied=false）。
  • 沒有正式核准的 limit profile。

這些都是要先補齊的前置條件。

3D 檢視器會不會連到儀器或外部網站？

不會。它只呈現外觀，不建立儀器連線、不送出 SCPI、不啟用 RF，而且不依賴外部 CDN，模型與檢視器都是本機資產。載入失敗時會保留靜態圖並提供重試。

output 資料夾越來越大怎麼辦？

這是正常的 —— 每次執行都獨立存檔就是為了可追溯。請自行定期把重要的 run 備份到別處，再清理舊資料。「紀錄」頁也提供移除功能。清理前請先確認該次結果沒有被任何報告或稽核文件引用。

我想新增一個功能，該從哪裡開始？

按順序讀這幾份：

  1. SPEC.MD —— 權威需求與安全邊界
  2. AGENTS.md —— 程式註解、文件語言、實機安全與開發規則
  3. docs/development-workflow.md —— Definition of Done

規則是：程式碼、測試、相關文件與完成度資料來源必須同步更新。若牽涉 SCPI 變更，還必須附上官方 CMP180 文件、Command Help、Recorder 紀錄或受控實機證據。

CI（自動化檢查）會連公司的 CMP180 嗎？

不會，而且明文禁止。CI 只執行 unit 測試、Mock、設定檔驗證、Ruff 與非阻斷的 mypy。

UDBox上／下變頻盒（Up-Down Converter），用來轉換頻率。
venvPython 虛擬環境，把專案套件與系統隔離。
VSA / VSG向量訊號分析儀／向量訊號產生器。
Waveform (.wv)預先產生的訊號波形檔，載入儀器後播放。
YAML一種人類容易閱讀的設定檔格式，本專案用它描述儀器與量測參數。
