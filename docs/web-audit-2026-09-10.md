## 繁體中文

### 範圍與結論

檢視基準為 `main` 的 `17f8d79`，於 2026-09-09 深夜至 09-10 檢查正式前端 `src/cmp180_evm/web/static/`。本次已實作首頁 CMP180 360° 檢視器；以下其他項目為下一階段計畫，尚未修改其操作邏輯。

已檢查首頁、量測、Loopback、HIL 批次、校正、結果、歷史紀錄、說明共 8 個工作區，包含桌面 1440px、手機 390px、中文／英文，以及 3D 深色／淺色。主要 UI 操作在獨立 `127.0.0.1:8766 --demo-only` 服務進行；原 `8765` 只讀取模式與頁面，當時回報 `custom-hardware`。沒有連接儀器或新增實機 RF 量測。

目前的優點值得保留：有明確的量測類型、後端安全驗證、INVALID 與 compliance 分層、可追溯 artifacts、唯讀歷史比較與可復原刪除。下一階段最重要的是讓「我現在在哪個模式、是否仍有工作執行、接下來該做什麼」在所有尺寸都清楚。

### 已完成：360° 檢視器

- 真正 GLB 立體模型，可水平拖曳旋轉 360°、滑鼠／觸控／鍵盤操作、縮放、正面／背面／側面、重設、自轉與全螢幕。
- 按需載入本機依賴；靜態圖備援、錯誤重試、離開畫面暫停自轉、減少動態偏好。
- 398 個網格降至 21 組，保留全部 316,668 個三角面；模型約 10.70 MB 降至 7.21 MB。
- 原始 Blender 資產保留。本次是互動化與載入最佳化；把手色澤、側網細節、背板文字仍是外觀估算。
- 實測手機觸控旋轉角度由約 0.61 變成 −2.27 rad，元件無橫向溢出；按鈕至少 44px；記錄到的外部請求與非 GET 請求均為零。
- 故意讓 GLB 回傳 HTTP 503，確認圖片保留；恢復下載後在同一頁重試成功。

操作與重建方式見 [3D 檢視器指南](cmp180-3d-viewer.md)。

### 建議實施順序

1. **第一階段：模式與工作狀態（A01、A02、A03、A07）**。約 2–3 個開發日。先建立狀態契約與 Mock 案例，再做狀態列、模式預設、工作恢復、錯誤提示。這是建議下一步。
2. **第二階段：手機與可操作性（A04、A05、A06、A08）**。約 2–3 個開發日。先解決版面、標籤與空狀態，再補完整翻譯；以全部 8 頁的桌面／手機矩陣驗收。
3. **第三階段：資訊精簡與維護（A09、A10）**。約 1–2 個開發日。收斂首頁、整理結果匯出名稱（互動圖 PNG／報告 PNG）、逐區拆分程式。低階手機測試若顯示 3D 延遲，再加入保留細節的低多邊形版本。

時程為單人開發估算，未包含實機 HIL 排程。第一階段不擴大 RF 功率、路徑或可執行 profile；新的實機量測仍依現場 SOP 單獨驗收。

## English

### Scope and conclusion

The baseline is `main` at `17f8d79`, reviewed overnight on September 9–10, 2026, using the supported frontend in `src/cmp180_evm/web/static/`. The CMP180 360° viewer is implemented in this change. Other findings below are planned work; their operating logic has not been changed.

All eight workspaces were reviewed: Home, Measurement, Loopback, HIL Campaign, Calibration, Results, History, and Guide. Coverage included 1440px desktop, 390px mobile, Chinese/English, and viewer dark/light themes. Interactive review used a separate `127.0.0.1:8766 --demo-only` service. The original 8765 service was inspected read-only and reported `custom-hardware`. No instrument connection or new live RF measurement was performed.

Preserve the useful foundations: distinct measurement types, backend validation, INVALID/compliance separation, traceable artifacts, read-only historical comparison, and recoverable deletion. The next phase should make the current mode, ongoing work, and next action clear at every screen size.

### Completed: 360° viewer

- Real GLB rendering with unrestricted horizontal orbit, mouse/touch/keyboard controls, zoom, front/rear/side views, reset, optional auto-rotation, and fullscreen.
- Local opt-in loading, still-image fallback, retry, visibility-based rotation pausing, and reduced-motion handling.
- 398 meshes joined into 21 groups, retaining all 316,668 triangles; approximately 10.70 MB reduced to 7.21 MB.
- Editable Blender assets remain. This is an interaction/loading upgrade, not a new precision model; handle color, ventilation, and rear labels remain approximations.
- Mobile touch changed orbit from approximately 0.61 to −2.27 radians without page overflow; controls were at least 44px tall. Observed external requests and non-GET requests were both zero.
- A deliberately injected HTTP 503 preserved the poster; retry succeeded on the same page after restoring the resource.

See the [viewer guide](cmp180-3d-viewer.md) for controls and rebuilding.

### Recommended sequence

1. **Mode and job state: A01/A02/A03/A07**, approximately 2–3 developer days. Define the status contract and Mock cases first, then implement mode display, defaults, reattachment, and error states. This is the recommended next step.
2. **Mobile and operation: A04/A05/A06/A08**, approximately 2–3 days. Fix layout, labels, and empty states, then complete translation. Accept against the eight-workspace desktop/mobile matrix.
3. **Information and maintenance: A09/A10**, approximately 1–2 days. Simplify Home, distinguish interactive-chart PNG from report PNG, and extract modules incrementally. Add a carefully reviewed lower-detail model only if device testing shows the current viewer is too slow.

Estimates assume one developer and exclude HIL scheduling. Phase one does not expand RF power, routing, or approved profiles. New live measurements still require the site SOP and separate acceptance.

- Browser inspection was cross-checked against source. One existing Demo power sweep displayed HISTORY/READ ONLY and a three-point chart. No new hardware evidence was generated.
