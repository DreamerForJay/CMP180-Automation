## 開始前確認

沒有 CMP180 時，請使用模擬模式。模擬、預覽、已保存結果分析與網頁展示都不會產生新的實機證據。

實機操作前，確認電腦位址、儀器位址、網路連線、RF1.1 至 RF1.5 接線、線材與衰減器、頻率、頻寬、功率、DUT 輸入上限與分析儀輸入上限。任何一項不確定時先停止，不要開啟射頻。

## 原始碼模式安裝

在 PowerShell 執行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,hardware]"
```

先驗證設定：

```powershell
python -m cmp180_evm validate-config configs\instrument.example.yaml
python -m cmp180_evm validate-config configs\wlan_baseline.example.yaml
```

## Windows 可攜版

把 `dist/CMP180-Windows-x64.zip` 完整解壓縮到可寫入資料夾，再雙擊 `CMP180.exe`。不要只複製執行檔；網頁資源、範例設定與相依檔案都必須留在同一個發布資料夾。

雙擊預設啟動模擬模式並開啟 `http://127.0.0.1:8765`。瀏覽器沒有自動開啟時可手動輸入網址；埠號被占用時使用 `CMP180.exe --port 8766`。結果寫入執行檔旁的 `output/`，完成後回到主控台按 Ctrl+C。

實機操作必須先閱讀[硬體量測標準作業程序](hardware-test-sop.md)，再以 `CMP180.exe --hardware` 啟動。可攜版不包含新的實機驗證，也不會自動替操作員確認接線或衰減器。

## 設定檔驗證

儀器設定檔保存位址、連接埠與基本連線資料；WLAN 基準設定檔保存頻率、頻寬、功率與預期結果。設定檔通過格式驗證，不代表命令、路徑或硬體條件已核准。

需要檢查命令列與測試環境時：

```powershell
.\.venv\Scripts\python.exe -m cmp180_evm test-connection --mock
.\.venv\Scripts\python.exe -m cmp180_evm dry-run `
  --instrument-config configs\instrument.example.yaml `
  --config configs\wlan_baseline.example.yaml
```

模擬連線只回傳替身識別與空錯誤佇列；預演只列出步驟，兩者都不會連線儀器或啟動量測。

## 模擬模式

啟動網頁：

```powershell
python -m cmp180_evm.web --demo-only
```

首頁右上角可切換中文／英文。模擬模式提供單次量測、頻率掃描、功率掃描、星座圖、MCS 掃描、進階功率示範、歷史結果與圖表。所有模擬結果會標記 `source=mock`、`simulated=true` 或 `hil_status=HIL_PENDING`，不能當作 CMP180 實測或合規結果。

### 星座圖

選擇調變方式、點數、雜訊與失真參數後產生資料。圖表支援縮放、平移、等比例座標、游標與離群點，工具列可匯出圖形與表格。硬體擷取介面目前會拒絕執行，避免送出未驗證命令。

### MCS 掃描

輸入 0 至 13 的逗號分隔清單，例如 `0,3,5,7,9,11`，再設定頻寬、中心頻率與模擬抖動。結果提供 EVM、功率、頻率誤差、可靠度與有效性，並可切換兩種圖表。這是軟體與模擬功能，尚無實機波形對應證據。

## 網頁工作站功能

### 單次量測

填寫條件後按檢查計畫，確認路徑、功率與操作員條件，再完成最後射頻確認。系統會在量測前讀回設定，並在成功、錯誤、逾時或取消時停止量測、關閉射頻與保存狀態。

### 頻率／功率掃描

固定核准區段可直接執行；每一點會保存原始回應與有效性。掃描可在點與點之間暫停，恢復時從下一點繼續；停止會保存部分結果。自訂條件若出現 `INV` 或未通過閘門，系統會停止後續點。

### GPRF 功率與 P1dB

輸入線損、輸出線損、外部增益與衰減器後，系統會計算輸入功率、輸出功率與增益。沒有觀察到增益下降 1 dB 時，結果顯示找不到 P1dB，不會把最後一點誤稱為 P1dB。分析儀安全上限不能由網頁欄位覆寫。

結果圖把指標切到 PA Pin、PA Pout 或 PA Gain 後，可按「對標 P1dB」把該次量測的 P1dB 內插點釘成基準標記，圖上以橘色對標線標出位置；再用「標記」模式點選測點，每個標記也會畫出到兩軸的對標線。圖表下方的比較面板列出各標記的 X、Y 與相對基準的 ΔX／ΔY：以 P1dB 為基準時 ΔX 就是相對 IP1dB 的 back-off，負值代表標記仍在 P1dB 之下。若目前不是功率掃描、指標不是 PA 欄位，或該次結果的 P1dB 是找不到或點數不足，按鈕會拒絕並說明原因，不會用最後一點假裝成 P1dB。切換指標會清除標記，避免不同量綱混用；P1dB 是相鄰實測點的內插值，不是實際量到的測點。

### 歷史紀錄

結果頁可載入已保存資料，查看單筆或比較多筆，調整曲線名稱、顏色、線型與點型，並匯出圖形與整理後表格。這些操作只讀取 `output/`，不會重新連線儀器。

比較多筆功率掃描時，每筆紀錄會以自己的曲線顏色畫出各自的 P1dB 對標線，比較面板並列出各筆的 IP1dB、OP1dB、P1dB 增益，以及相對第一筆的 ΔIP1dB／ΔOP1dB（只列出已求得 P1dB 的功率掃描）。接線、衰減器、波形或校正不同的紀錄之間的差值只能當成觀察值，不得直接宣稱成 DUT 差異或合規結論。

## 離線結果分析

保存量測後可離線重建圖表與報告：

```powershell
python scripts\plot_results.py output\<執行資料夾>\results.csv
python scripts\build_report.py output\<執行資料夾>
python -m cmp180_evm validate-limits configs\limits.example.yaml
python scripts\build_v1_acceptance.py --evidence output\<實機資料夾>
```

這些指令只讀取設定與已保存檔案，不會送出命令。常見輸出包括 `results.csv`、結構化資料、設定快照、原始回應、錯誤佇列、圖形與有效性摘要。

## 第一次連接實機

只有在離線測試通過、工作區狀態清楚、儀器沒有執行中的量測、位址正確且接線已確認後才連接。先執行只讀連線檢查：

```powershell
.\.venv\Scripts\python.exe -m cmp180_evm test-connection `
  --instrument-config configs\instrument.example.yaml
```

這一步只允許識別、選項與錯誤佇列查詢。完整規則請看[唯讀硬體驗證](hardware-readonly-validation.md)。

## 實機量測流程

1. 閱讀[硬體量測標準作業程序](hardware-test-sop.md)，確認路徑、頻率、頻寬、功率、線損與輸入限制。
2. 啟動網頁工作站，選擇單次量測或固定核准掃描。
3. 按檢查計畫，修正所有安全或設定錯誤。
4. 完成接線、操作員在場與最後射頻確認。
5. 執行後觀察有效性、可靠度、錯誤佇列、最終量測狀態與射頻狀態。
6. 從 `output/` 保存完整資料夾，不要只保存圖檔。

已核准的固定設定有實機證據；超出核准頻率、頻寬、功率、路徑或治具的結果，必須標示為待驗證，不能直接作為合規結論。

## 限制與安全邊界

- 不得在未要求時重設儀器或工作區。
- `FETCh` 讀取已保存結果；`READ` 與 `INITiate` 會啟動量測。
- 所有射頻流程都必須以清理流程結束，嘗試停止／中止量測並關閉射頻。
- 未經官方資料、內建說明或受控探索證實的命令，必須維持空值。
- 模擬、預演、網頁預覽、已保存結果分析與 CMsquares 操作，都不能描述為新的完整 Python 實機量測。
- 自訂實機掃描曾出現 `INV`，在重新驗收前不可宣稱通過。

## 問題排查

### 網頁沒有開啟

確認主控台仍在執行，查看顯示的網址，或手動開啟 `http://127.0.0.1:8765`。埠號衝突時改用 `--port 8766`。

### 執行檔啟動失敗

確認壓縮檔已完整解壓縮，且執行檔旁的資源資料夾沒有被移動。請不要從壓縮檔內直接執行，也不要只複製執行檔。

### 結果為無效

先查看輸出中的有效性、可靠度、錯誤佇列與最終射頻狀態。無效結果不是合規失敗，也不是成功；先停止後續射頻，確認接線、頻寬、波形與功率，再依標準作業程序重新判斷。

### Git 顯示路徑不受信任

只把確定的專案路徑加入 Git 安全清單，不要加入整顆磁碟或萬用字元：

```powershell
git config --global --add safe.directory <專案路徑>
git config --global --get-all safe.directory
```
